# R2：改密码与登录失效（零基础教学交接）

日期：2026-10-04。主对话亲手实现，教学对话只负责解释。

当前运行和测试入口见 [README](../README.md)，备份恢复步骤见 [部署说明](../Render部署教程-图文版.md)，进度见 [TODO](../TODO.md)。

## 问题：密码与已经登录的凭据不是一回事

密码用于“领取门票”：登录时后端检查密码，然后签发 JWT。
浏览器之后拿 JWT 请求管理接口，不会每次再提交密码。
因此只改密码哈希，不会使已经签发、最长 24 小时有效的 JWT 自动消失。

修复前：改密码后，拿着旧 JWT 请求 /api/me 仍返回 200。

## 修复：给账号和门票都标一个版本

账号有 tokenVersion；登录时 JWT 也记录当时版本。
鉴权除了验证签名、有效期和用户存在，还要求 JWT 版本等于账号当前版本。

例子：账号版本 0，两个设备的门票都写 0。改密码把账号版本变成 1。
旧票仍有正确签名，但版本 0 不匹配 1，因此返回 401。
用新密码重新登录领取版本 1 的门票，就能进入。

版本不是秘密，不是密码；不能仅靠修改版本“伪造登录”，JWT 仍须通过签名验证。

## 实际代码

- server.js：validateDatabase 验证可选 tokenVersion 为非负安全整数；新账号初始为 0。
- 登录 /api/login：签发 JWT 时带 tokenVersion；旧数据库没有字段时按 0。
- auth：拒绝没有版本的旧 JWT，或版本与当前用户不符的 JWT。
- /api/account：密码通过检查后生成哈希、版本加 1，再一起 commit；失败不会保存半成品。只改用户名不增加版本。
- public/js/admin.js：收到 requiresReauthentication 后清除当前令牌并重新登录。
- public/js/api.js：redirectToLogin(true) 保留返回路径，携带 passwordChanged 提示标志。
- public/js/login.js：显示“密码已更新，原有登录已失效，请使用新密码重新登录”。

改密码者当前会话也退出；其他设备无需实时弹窗，下一次受保护请求即被拒绝。
其他管理员的版本不变，因此其登录不受影响。公开图谱无需令牌，继续可访问。
旧数据库可直接读取，无需修改真实账号文件；升级前旧 JWT 一次性要求重新登录。
版本保存在数据库，重启不会还原。若手工恢复旧备份，需同时轮换 SECRET，否则版本回退可能恢复旧令牌的权限。

## 验证

node --test：11 项通过。新增用例覆盖旧库缺字段、无版本令牌、密码太短拒绝、真实用户名修改不退出、多会话令牌失效、旧令牌不能写人员或再次改密码、新旧密码、其他管理员不受影响，以及重启后旧票仍无效、新票仍可用。

scripts/account.browser.cjs：真实 Chrome、临时数据库、两个独立浏览器会话。
操作实际登录页面和账号表单，检查当前会话清空令牌并显示提示，另一个会话刷新后被带回登录；旧密码失败、新密码成功。
测试不会改真实数据库。Playwright 使用本机已有安装，没有添加生产依赖。

手工运行浏览器用例：node scripts/account.browser.cjs，需已有 Playwright 与 Chrome；PLAYWRIGHT_MODULE 可指向已有 Playwright 安装。
