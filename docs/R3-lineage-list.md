# R3：遍历列表不等于师承路径

日期：2026-10-04。代码由主对话亲手修改，教学对话只解释。

当前运行和测试入口见 [README](../README.md)，全项目进度见 [TODO](../TODO.md)。

## 一个最小例子

A 和 B 都教过 C，实际关系是 A→C、B→C，A 和 B 之间没有关系。
原 findAncestors 用栈遍历，可能先找到 B，再找到 A，于是返回 [B, A]。
这表示“找到这两位上游人物”，不表示“B 和 A 相连”。
原页面把它们用箭头串起来并标为师承路径，显示 B←A，便凭空表达了 A→B。
单链也可能产生误导：遍历次序与按箭头展示的真实顺序不一定一致。

## 三个概念

- 上游人物集合：所有能沿师承关系回溯到的人，包含谁，不包含展示顺序的意义。
- 遍历列表：程序按某种搜索顺序找到这些人的结果。栈通常后进先出。
- 路径：一串相邻人物之间确实存在对应边的序列。多师傅通常会产生多条路径。

因此不能仅用 join('←') 就把任意遍历结果变成真实路径。

## 实际修复

public/index.html 的 showInfoPanel：

1. 保留 findAncestors 的去重回溯逻辑。
2. 展示前按 generation、姓名、ID排序，让列表顺序稳定。generation 是图关系计算的代数，不是人物真实年龄或出生时间。
3. 标题改为“历代师承（人数）”。
4. 每个人仍是独立可点击的标签，join('') 不再插入箭头。
5. 直接师傅、徒弟栏目仍取真实的相邻关系；祖师显示 0 人及原来的空状态文字。

这次没有枚举所有完整路径。共同祖先可能属于多条路径，但只在人物列表中出现一次。
图谱布局、大小、配色、数据和后端未改动。

## 验证

scripts/lineage.browser.cjs 读取实际 HTML 和脚本，在真实 Chrome 里调用实际 processData、findAncestors、showInfoPanel。
测试数据全部在浏览器内存中，不请求 API，不修改真实数据库。

检查单链、多师傅、菱形共同祖先只出现一次、祖师空状态、特殊字符姓名、独立标签没有关系箭头、直接师傅/徒弟内容。
点击祖先标签后验证真实点击处理器选中了正确 ID 并更新详情；仅把 selectAndFocus 的摄像机动作替换为记录目标，未测试完整摄像机动画。
R1 的 scripts/avatar.browser.cjs 同时回归通过。

手工运行：node scripts/lineage.browser.cjs，需已有 Playwright 和 Chrome；PLAYWRIGHT_MODULE 可指向本机已有安装。未增加生产依赖。

## 教学节奏

先画 A、B 同时连接 C 的三个人示例，再解释列表为什么不是路径。
然后看 findAncestors 的 visited、stack，最后对比 .join('←') 与独立标签展示。
一次讲一个概念，不要求初学者先掌握图论术语。
